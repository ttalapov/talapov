Що таке Docker?

Docker — це платформа для розробки, доставки та запуску застосунків у контейнерах. Контейнер — ізольоване середовище, що містить усе необхідне для роботи застосунку: код, runtime, бібліотеки, змінні оточення.

💡 Ключова ідея "Build once, run anywhere" — зібрав один раз, запускай будь-де: на ноутбуці, сервері, у хмарі.

Ключові концепції

Image (Образ)

Docker Image — шаблон лише для читання з набором шарів файлової системи. Образ описує стан застосунку: ОС, залежності, файли, команди. Образи зберігаються у реєстрах (Docker Hub, GitHub Container Registry, AWS ECR).

Container (Контейнер)

Контейнер — запущений екземпляр образу. Можна запустити кілька контейнерів з одного образу. Контейнер має власний filesystem, мережу та процеси, але ділить ядро ОС з хостом.

Registry (Реєстр)

Сховище образів. Docker Hub — публічний реєстр за замовчуванням. Образи мають теги: nginx:latest, node:20-alpine.

Volume (Том)

Механізм персистентного зберігання даних поза lifecycle контейнера. Дані у volume живуть після зупинки чи видалення контейнера.

Network (Мережа)

Docker має власний networking. Контейнери в одній мережі можуть спілкуватися за іменем. Основні драйвери: bridge, host, overlay.

Архітектура Docker

Docker використовує клієнт-серверну архітектуру:

  • Docker Client (docker) — CLI, який ти використовуєш. Надсилає команди до daemon.
  • Docker Daemon (dockerd) — фоновий процес, що управляє образами, контейнерами, мережами та томами.
  • Docker Registry — зберігає та роздає образи. За замовчуванням — Docker Hub.
  • containerd — низькорівневий runtime для управління lifecycle контейнерів.
✅ Запам'ятай Lifecycle контейнера: create → start → running → stop → remove. Образ — незмінний. Контейнер — запущений примірник з власним writable шаром.

Шари образу (Union File System)

Кожна інструкція у Dockerfile створює окремий шар. Шари кешуються та перевикористовуються — це робить збірку і завантаження образів ефективними.

Шари образу (логічно) 
┌────────────────────────────────────┐  ← Writable Container Layer
├────────────────────────────────────┤
│  COPY . .                          │  ← Layer 4 (Ваш код)
├────────────────────────────────────┤
│  RUN npm install                   │  ← Layer 3 (npm deps)
├────────────────────────────────────┤
│  COPY package*.json ./             │  ← Layer 2
├────────────────────────────────────┤
│  FROM node:20-alpine               │  ← Layer 1 (base image)
└────────────────────────────────────┘
⚠️ Важливо для кешування Зміна шару інвалідує всі наступні шари. Тому спочатку копіюємо package.json, встановлюємо залежності, і лише потім копіюємо код — так npm install кешується.

Dockerfile

Dockerfile — текстовий файл з інструкціями для побудови образу. Кожна інструкція виконується у окремому шарі.

ІнструкціяОписПриклад
FROMБазовий образFROM node:20-alpine
WORKDIRРобоча директоріяWORKDIR /app
COPYКопіювати файлиCOPY . .
RUNВиконати команду (під час build)RUN npm install
ENVЗмінна оточенняENV NODE_ENV=production
EXPOSEДокументує портEXPOSE 3000
CMDКоманда за замовчуванням (run-time)CMD ["node", "index.js"]

HEALTHCHECKПеревірка здоров'яHEALTHCHECK CMD curl -f http://localhost/

Production-ready Dockerfile для Node.js

Dockerfile 
# ── Stage 1: deps ──────────────────────────────────────
FROM node:20-alpine AS deps
WORKDIR /app

# Копіюємо лише package файли (кешування!)
COPY package*.json ./
RUN npm ci --only=production

# ── Stage 2: build ─────────────────────────────────────
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# ── Stage 3: runtime ───────────────────────────────────
FROM node:20-alpine AS runtime
WORKDIR /app

# Не запускати як root
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

COPY --from=deps  /app/node_modules ./node_modules
COPY --from=build /app/dist        ./dist

ENV NODE_ENV=production
ENV PORT=3000

EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -qO- http://localhost:3000/health || exit 1

CMD ["node", "dist/index.js"]
✅ Multi-stage build Multi-stage build дозволяє зменшити фінальний образ — dev-залежності та build-артефакти не потрапляють в production image. Типовий образ зменшується з ~1GB до ~100MB.

Docker Compose

Docker Compose — інструмент для визначення та запуску багатоконтейнерних застосунків через один YAML-файл. Ідеальний для локального розробницького середовища.

Типовий стек: Node.js + PostgreSQL + Redis

docker-compose.yml 
version: "3.9"

services:

  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgresql://user:pass@db:5432/mydb
      - REDIS_URL=redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    volumes:
      - .:/app                    # hot-reload у розробці
      - /app/node_modules         # анонімний volume для modules
    networks:
      - internal

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: mydb
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user"]
      interval: 5s
      retries: 5
    networks:
      - internal

  redis:
    image: redis:7-alpine
    networks:
      - internal

volumes:
  pgdata:

networks:
  internal:
    driver: bridge

Основні Compose-команди

terminal 
# Запустити всі сервіси у фоні
docker compose up -d

# Зупинити і видалити контейнери
docker compose down

# Зупинити + видалити volumes
docker compose down -v

# Перебудувати образ і запустити
docker compose up --build

# Логи конкретного сервісу
docker compose logs -f app

# Запустити команду всередині сервісу
docker compose exec db psql -U user mydb

Мережа та безпека

Типи мереж

bridge

За замовчуванням. Ізольована мережа на одному хості. Контейнери спілкуються за іменем.

host

Контейнер ділить мережу з хостом. Максимальна продуктивність, мінімальна ізоляція.

overlay

Для Docker Swarm / Kubernetes. З'єднує контейнери на різних хостах.

none

Повна ізоляція. Контейнер без мережевого доступу.

Best Practices безпеки

  • Не запускати контейнери від root-користувача — використовуй USER
  • Використовуй офіційні minimal образи (alpine, distroless)
  • Регулярно оновлюй базові образи — стеж за CVE
  • Не зберігай секрети у Dockerfile або змінних оточення. Використовуй Docker Secrets або Vault
  • Обмежуй capabilities: --cap-drop ALL
  • Read-only filesystem: --read-only
  • Скануй образи: docker scout cves або Trivy
⚠️ Секрети у Docker Ніколи не hardcode паролі та API ключі у Dockerfile або docker-compose.yml. Використовуй .env файл (у .gitignore) або Docker Secrets для production.

🛠 Практичне заняття

Контейнеризація full-stack застосунку з нуля. Час виконання: ~90 хвилин

Мета

Розгорнути застосунок Todo API (Node.js + Express + PostgreSQL) у Docker-контейнерах з використанням Docker Compose.

Підготовка середовища

  1. Встановити Docker Desktop Завантажити з docs.docker.com/get-docker. Перевірити: docker --version та docker compose version
  2. Клонувати стартовий проєкт git clone https://github.com/your-org/docker-workshop-starter або створити структуру вручну (дивись нижче)
  3. Перевірити Docker daemon docker info — має показати інформацію без помилок

Структура проєкту

│   │   ├── index.js
│   │   └── db.js

Завдання 1 Dockerfile для Backend (Node.js) easy

Напишіть backend/Dockerfile за наступними вимогами:

  • Базовий образ: node:20-alpine
  • Робоча директорія: /app
  • Спочатку копіювати package*.json, потім виконати npm ci
  • Потім копіювати решту файлів
  • Expose порт 3000
  • CMD: node src/index.js

Перевірка:

terminal 
docker build -t todo-backend ./backend
docker run -p 3000:3000 todo-backend
# http://localhost:3000/health → {"status":"ok"}
Завдання 2 Dockerfile для Frontend (Nginx) easy

Напишіть frontend/Dockerfile для роздачі статики через Nginx:

  • Базовий образ: nginx:alpine
  • Скопіювати вміст директорії в /usr/share/nginx/html
  • Expose порт 80
💡 Підказка Для SPA (React/Vue) також потрібно налаштувати try_files $uri /index.html у конфігурації nginx щоб client-side routing працював.
Завдання 3 Docker Compose — повний стек medium

Напишіть docker-compose.yml з трьома сервісами:

  • db — PostgreSQL 16 з named volume і healthcheck
  • backend — збирається з ./backend, залежить від db, порт 3000
  • frontend — збирається з ./frontend, порт 80

Усі три сервіси повинні бути в одній мережі app-network.

Секрети (POSTGRES_PASSWORD, DATABASE_URL) — винести у .env файл.

Перевірка:

terminal 
docker compose up -d
docker compose ps
# Всі три сервіси: Status = running (healthy)

curl http://localhost:3000/api/todos   # [] або список todos
curl http://localhost:80               # HTML сторінка
Завдання 4 ⭐ Nginx reverse proxy + Multi-stage hard

Додайте сервіс nginx як reverse proxy, який:

  • Роздає статику фронтенду на /
  • Проксіює /api/* на backend-контейнер
  • Додайте rate limiting: не більше 10 запитів/секунду

Рефакторингу backend Dockerfile у multi-stage build:

  • Stage 1 (deps): лише production залежності
  • Stage 2 (runtime): фінальний image на основі node:20-alpine
  • Запуск від non-root користувача

Бонус: додайте HEALTHCHECK для backend.

🎯 Результат Один порт :80 для всього застосунку. Розмір backend image — менше 150MB.
